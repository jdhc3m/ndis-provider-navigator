# 01 — Register ingestion

## What we built

The first real data path: a script downloads the NDIS Commission provider register CSV (about 42 MB, 64,734 rows) and refuses to keep it unless it is plausibly complete; pure functions in `domain/register.py` turn each raw row into a `Provider` and an `Outlet` and merge the many rows that share one ABN; a `ProviderRepository` port and a `ListProviders` use case sit in `application/`; the SQLite repository and the CSV loader live in `adapters/`; and `GET /providers` exposes filters for state, postcode, registration group, status and a Brisbane flag. The whole national register is loaded, with `brisbane_area` as a flag rather than a filter at load time.

## Concepts

- **Port and adapter:** `ProviderRepository` is a `typing.Protocol` with two methods, `replace_all` and `find`. `application/` codes against it; `adapters/sqlite_repository.py` implements it. Same idea as a Kotlin `interface ProviderRepository` in a pure module with a Room implementation in the app module. `src/ndis/application/providers.py`, `src/ndis/adapters/sqlite_repository.py`.
- **Structural typing:** a class satisfies a `Protocol` by having the right methods; it never declares `implements`. mypy checks it, like Kotlin's interface conformance, but without the keyword. The test fake in `tests/` satisfies the same port.
- **Frozen dataclasses as value objects:** `Provider`, `Outlet`, `RegistrationGroup` are `@dataclass(frozen=True)`, the equivalent of a Kotlin `data class` with `val`s. Merging returns a new object instead of mutating one. `src/ndis/domain/entities.py`.
- **Pure parsing functions:** `parse_address_tail`, `website_domain`, `split_registration_groups`, `parse_register_date`, `merge_provider_rows` take strings and return values, no IO, so each has a tiny exact-match test. `src/ndis/domain/register.py`.
- **Download verification:** write to a `.part` file, then promote it only if size > 30 MB and distinct ABNs > 25,000. The site returns a truncated file to non-browser clients, which looks like success. `scripts/fetch_public_data.py`.
- **Atomic refresh:** `replace_all` deletes and reloads inside one transaction, so a reader never sees a half-loaded register.

## Decisions and why

- **Load the whole national register, flag Brisbane.** The brief scopes answers to Brisbane, but ticket 03 must match private Maps records against any ABN, and `state=` should work everywhere. Alternative rejected: filtering to Brisbane rows at load time, which would make 29,574 − 2,403 providers invisible to entity resolution.
- **`state`/`postcode` match head office OR any outlet.** A provider headquartered in Sydney with a Brisbane outlet is a Brisbane provider for the user. Alternative rejected: head office only (simpler SQL, wrong answers).
- **Per-ABN merge: Approved beats Revoked, then later expiry.** The Reviewer found 4 ABNs that were revoked and then re-registered; first-row-wins stored them as Revoked. The fix is a `rank()` key over `(is_approved, expiry)` in `merge_provider_rows`, with `brisbane_area` OR-merged.
- **One `Outlet` row per register row even when blank.** 27,877 rows have no outlet name or address. Keeping them preserves the row count for provenance checks; dropping them would hide data loss behind a filter.
- **`httpx` added to the dev group only.** FastAPI's `TestClient` needs it. No runtime dependency added; the lock was regenerated by CI as per ticket 00.
- **Unknown `status` returns 422, matching is case-insensitive.** Validate at the edge, normalise in `application/normalise_query`, keep SQL simple.

## How to say it in an interview

"The register is a 42 MB CSV with 64,734 rows but only 29,574 distinct ABNs, because one provider has many outlets. I split the work along hexagonal lines: pure domain functions parse and merge rows — frozen dataclasses, no IO, each with exact-match tests — the application layer defines a repository Protocol and a `ListProviders` use case, and the adapters implement SQLite via SQLAlchemy and load row by row inside one transaction. The download step verifies size and distinct-ABN count before keeping the file, because the source silently truncates for non-browser clients. The independent reviewer caught a real data bug: four providers that were revoked and re-registered were stored as Revoked under first-row-wins, so the merge rule is now Approved-beats-Revoked then latest expiry. All 115 tests run in about a second against a temp SQLite file; no mocks of SQLAlchemy."

## Numbers

- 115 tests, inner-layer coverage 99.03%, import-linter contracts 2 kept.
- Register: 42,507,782 bytes, 64,734 rows, 0 rejected (parse ratio 1.0000), 29,574 providers (Approved 27,363, Revoked 2,211), 64,734 outlets, 6,246 Brisbane rows across 2,403 ABNs.
- `GET /providers?postcode=4101&status=Approved` → 40 results.
- 2 review rounds: 1 must-fix and 4 nits in round 1, 0 in round 2.
- CI `quality` job: 10 s on the lock-mismatch run, 19 s on the green run <https://github.com/jdhc3m/ndis-provider-navigator/actions/runs/42525946139>. PR: <https://github.com/jdhc3m/ndis-provider-navigator/pull/19>.
