# Evaluation suite

The eval gate is `uv run pytest -m eval --no-cov`. It enforces the floors in
`thresholds.yaml` — filter accuracy ≥ 0.85, rule hit@3 ≥ 0.7, extraction macro
precision ≥ 0.8 on labelled rows, refusal recall = 1.0 — and never gets green by
lowering them. Each suite replays a committed capture or a recorded cache where one
exists, so a gate run spends no model quota; the model-backed values were captured
from the configured endpoint (see `GET /meta` and `src/ndis/config.py`).

CI runs the suites that need nothing but committed files — `test_intent_accuracy.py`
replays `intent_cache.yaml` through the real parser and pins the intent prompt's
contract — and the suites that need `data/` (the register snapshot, the rule index,
the private extraction and embedding caches) skip with their reasons printed and a
workflow notice. Those floors stay enforced on machines with the data; CI never
claims they passed.

`test_intent_accuracy.py` is the prompt-contract half of the gate: the replayed
captures cannot see a prompt edit, so the suite pins the intent prompt's load-bearing
declarations (question-as-data, ignore-embedded-instructions, exact output shape)
directly, the way `domain/answer.py` pins the caveat constant.

`er_sample.yaml` is the entity-resolution hand-check sample written by
`scripts/resolve_entities.py` (50 rows, stratified by `match_status` × `strategy`; ambiguous
rows list their register candidates). Fill each
`verdict:` with `correct`, `incorrect` or `unsure`; `test_entity_resolution.py` then
reports precision over the filled labels and skips visibly while none are filled.

`judge_verdicts.yaml` is the judge-faithfulness template (ticket 08): twenty
free-text answers the rule judge served with their citations. `verdict:` takes
`faithful`, `unfaithful` or `unsure`; `labelled_by:` records who labelled — the
building agent's ten initial labels are filled, the rest await the owner. Agreement
against the model judge's own supported verdict is reported with denominators in
`reports/cost.md`, regenerated by `scripts/cost_report.py` from the private
measurement runs under `data/private/cost/`.
