# Evaluation suite

The eval gate is `uv run pytest -m eval --no-cov`. It enforces the floors in
`thresholds.yaml` — filter accuracy ≥ 0.85, rule hit@3 ≥ 0.7, extraction macro
precision ≥ 0.8 on labelled rows, refusal recall = 1.0, service resolution ≥ 0.85,
follow-up accuracy ≥ 0.85, follow-up refusal recall = 1.0 — and never gets green by
lowering them. Each suite replays a committed capture or a recorded cache where one
exists, so a gate run spends no model quota; the model-backed values were captured
from the configured endpoint (see `GET /meta` and `src/ndis/config.py`).

Fast and slow halves. The suites that replay the full register snapshot
(`test_ask_golden.py`, `test_ask_graph_parity.py`) carry the `slow` marker: they take
minutes, so the default `uv run pytest` (which adds `-m 'not slow'`) leaves them out
during iteration. Run the full gate once before pushing — CI's eval job selects
everything again because its `-m eval` overrides the default. The fast subset on its
own is `uv run pytest -m 'eval and not slow' --no-cov`.

CI runs the suites that need nothing but committed files — `test_intent_accuracy.py`
replays `intent_cache.yaml` through the real parser and pins the intent prompt's
contract, and `test_chat_golden.py` replays `chat_cache.yaml` through the real chat
graph (its summaries pin the rewrite prompts, so the register is never queried) — and
the suites that need `data/` (the register snapshot, the rule index, the private
extraction and embedding caches) skip with their reasons printed and a workflow notice.
Those floors stay enforced on machines with the data; CI never claims they passed.

`chat_golden.yaml` (ticket 16) is the multi-turn counterpart: thirteen conversations of
two to three turns — narrowing by status, changing the place or registration group,
switching to a price or rule question, a follow-up decision request and a follow-up
prompt injection — replayed from `chat_cache.yaml` through the real chat graph. Since
ticket 17 the cache carries three sections: the contextualise payload per follow-up
turn (keyed by the digest of what the model saw), the intent payload per standalone
question, and the turn summary per conversation turn (the standalone question, parsed
intent and providers shown, exactly as the rewrite prompt carried it). The replay
rebuilds each follow-up's history exclusively from the cached summaries, so its prompts
are byte-identical to capture time and its own ask sections run over small seeded
fixture repositories — the eval queries no register and needs nothing but committed
files, so it runs in seconds everywhere, including CI. The enforcement logic itself is
unit-tested without the capture against a synthetic cache fixture
(`tests/test_chat_golden_logic.py`), including the case where a rewrite would launder a
refusal into an execution and the case where the replay's wiring differs from the
capture's (it must not matter any more).

`test_intent_accuracy.py` is the prompt-contract half of the gate: the replayed
captures cannot see a prompt edit, so the suite pins the intent prompt's load-bearing
declarations (question-as-data, ignore-embedded-instructions, exact output shape)
directly, the way `domain/answer.py` pins the caveat constant.

Re-capturing. `scripts/parse_intent_cache.py` rewrites `intent_cache.yaml` from the
configured model. After a prompt tweak or a reworded golden question, pass
`--only SUBSTRING` (repeatable) to capture just the matching questions and keep the
other payloads from the committed cache — a full 35-case capture spends a daily
quota; a targeted one spends minutes of it.

`er_sample.yaml` is the entity-resolution hand-check sample written by
`scripts/resolve_entities.py` (50 rows, stratified by `match_status` × `strategy`; ambiguous
rows list their register candidates). Fill each
`verdict:` with `correct`, `incorrect` or `unsure`; `test_entity_resolution.py` then
reports precision over the filled labels and skips visibly while none are filled.

`judge_verdicts.yaml` is the judge-faithfulness template (ticket 08): twenty
free-text answers the rule judge served with their citations. `verdict:` takes
`faithful`, `unfaithful` or `unsure`; `labelled_by:` records who labelled — the
building agent's ten initial labels are filled, the rest await the owner. Agreement
against the model judge's own supported verdict is reported with denominators in
`reports/cost.md`, regenerated by `scripts/cost_report.py` from the private
measurement runs under `data/private/cost/`.
